## The thesis, in one paragraph

Every CRM audit produces the same artifact: a number. *41% of accounts are missing industry.* That
number is a **symptom**, and symptoms are not actionable — they get onto a slide, someone buys an
enrichment vendor, and the number comes back next quarter because nobody found out where it came
from. Bad CRM data is not a fog that settles evenly; it is **produced**, by a small number of
identifiable mechanisms — a form that stopped collecting a field on a date, an import batch that
stamped four hundred records in one afternoon, an integration that ran once with the wrong mapping,
a rep who has never filled country in two years. Each has a **locus** (a cohort of records) and an
**onset** (a date it started, sometimes a date it stopped). This repo refuses to report a defect
rate without both. Underneath that sits a second lie: **completeness metrics count placeholders as
data**, so a field that is 98% populated and 40% `Other`/`N/A`/`Test Co`/`000-000-0000` reports as
healthy while everything downstream believes it. Every field here renders two numbers — **populated**
and **known** — and the gap between them is the product. Sibling repos own the neighbours: Day 003
`lead-cleaner` owns fixing, Day 018 `crm-duplicate-graph` owns duplicates, Day 030 `stage-validator`
owns stage-versus-activity, Day 025 `crm-timeline` owns activity records, Day 038 `revops-audit`
owns the scorecard, Days 011/013 own title and domain normalization. **Do not rebuild any of them
here.** Day 010's only claim is localizing defects to their origin, honestly.


`npm` is the committed package manager — README and lockfile stay npm even if bun is used locally,
because `npm install && npm run dev` is what a reviewer types without reading.

Five setup facts inherited from Days 001–009:

- Vitest config belongs in `vitest.config.mts` (`.mts`, not `.ts` — the extension is what stops
  Vite's config loader warning about ESM-in-CJS), and it globs `lib/**/*.test.ts` only. Tests
  outside `lib/` will not run.
- `tsc` alone fails on a clean checkout because `LayoutProps` and friends are generated into
  `.next/types`, so `typecheck` must run `next typegen` first. Never "fix" that error by editing
  `app/layout.tsx`.
- `tsconfig.json` sets `noUncheckedIndexedAccess` on top of `strict` — array and record access
  yields `T | undefined`. Handle it; do not reach for `!`.
- Scripts run through `vite-node -c vitest.config.mts` rather than bare `node`, because the engine
  uses extensionless relative imports that Node's ESM resolver rejects and the `@/` alias lives in
  the Vitest config.
- `AGENTS.md` is regenerated by `next dev`. Commit it with your work; deleting it from a diff only
  re-creates the uncommitted change.

## Architecture

```
                    ┌─ server component ──► data/*.ts (Zod-validated at import)
Browser ────────────┤
                    ├─ lib/diagnose (pure) ──► same functions client- and server-side
                    │
                    └─ POST /api/triage ──► key check ──► rate limit ──► model ──► Zod ──► Verdict[]
```

`lib/diagnose/` is the engine and is **dependency-free and framework-free** — it imports `zod` and
nothing else. Not `next`, not `react`, not `@/data`, not `@google/genai`, no DOM globals, no
`Date.now()`. An eslint `no-restricted-imports` rule scoped to that directory enforces it and the
package carries its own `README.md`. This is not stylistic: a diagnostic engine that cannot reach a
network client or a clock cannot emit a finding that isn't a consequence of its arguments.

| module | responsibility |
|---|---|
| `types.ts` | the contract — records, provenance, defects, cohorts, findings, onset |
| `schema.ts` | Zod schemas for patients and registries; parsed at import, throws on bad data |
| `detect/absent.ts` | field emptiness |
| `detect/counterfeit.ts` | six families — sentinel, structural, reserved, schema-default, batch-stamp, field-shift |
| `detect/contradiction.ts` | four kinds — mismatch, ordering, band, over declared mapping tables |
| `detect/orphan.ts` | referential breaks between contacts and accounts |
| `detect/index.ts` | the detector registry |
| `cohorts.ts` | enumeration over declared dimensions, conjunctions of depth ≤ 2, non-temporal |
| `stats.ts` | Wilson score interval, Bonferroni-adjusted z, Bernoulli log-likelihood |
| `onset.ts` | exhaustive single change-point, three onset classes |
| `attribute.ts` | conditioning, subsumption to a minimal locus, `CONFOUNDED` |
| `vitals.ts` | populated versus known, per field |
| `diagnose.ts` | the pipeline |
| `export.ts` | CSV serialisation, permalink encode/decode |

`data/` holds the seeded generator, the two committed corpora, the declared dimensions, the check
registry, the sentinel lists and the mapping tables. `lib/triage/` holds the Gemini call, prompt,
response schema and rate limiter. `app/` is the single console: Vitals · Findings · Cohorts ·
Records.

### The pipeline

```
patient
 ├─ 1. DETECT       every record × every check   ──► Defect[]     (pure, deterministic)
 ├─ 2. ENUMERATE    declared dims, depth ≤ 2     ──► Cohort[]     (count is exact and known)
 ├─ 3. TEST         Wilson vs base rate, n ≥ 20  ──► elevated | UNDERPOWERED
 ├─ 4. ATTRIBUTE    condition, subsume           ──► locus | CONFOUNDED | PERVASIVE
 ├─ 5. ONSET        change-point on the locus    ──► ONSET | HEALED | CHRONIC
 └─ 6. VITALS       populated vs known           ──► per-field pair
                                                     ↑
 (residue of step 1) ──► POST /api/triage ──► model verdicts, own column, never merged
```

Steps 1–6 are a pure function of the patient and the registries. The engine ships to the browser —
switching patient or toggling a detector must re-derive everything with no round trip.

**Dimensions, checks, mapping tables and sentinel lists are data, not code.** If you find yourself
writing `if (field === "industry")` inside `lib/diagnose/`, the fact belongs in `data/` as a
descriptor.

## Rules that are easy to break by accident

- **Never add a score.** Decision 26. No 0–100, no letter grade, no "CRM health: 68%", no severity
  weighting, no summing findings into a total. Day 001 owns weighted arithmetic and Day 038 owns
  the scorecard. Rates against a base rate with an interval *are* the unit here; aggregation across
  defect classes into one figure is the ban.
- **Never add a fix button.** Decision 24. No write, no suggestion, no normalized output, no merge.
  Diagnosis is not treatment. The instinct is strong and it turns this repo into a worse Day 003.
- **Never add duplicate detection.** Decision 25. No fuzzy matching, no similarity, no merge
  candidates. Dedupe is the first thing anyone thinks of under "CRM hygiene" and it belongs to
  Day 018 entirely.
- **Claims and non-claims never mix.** `UNDERPOWERED` is reported, counted in its own section, and
  never summed with claimed findings. Adding them destroys the meaning of the significance
  threshold — which is the only reason any number in this app can be believed.
- **Deterministic and model results never mix.** Model verdicts render in their own column. A
  verdict is a second opinion on a residue, not a detection.
- **A counterfeit value counts as absent for completeness.** `known ≤ populated` is an invariant
  asserted in the sweep for every field on every patient.
- **Time is not a cohort dimension.** Cohorts are non-temporal conjunctions of declared provenance
  dimensions. Time enters only through onset. Without this the same defect gets reported twice
  wearing different hats.
- **Cohort depth stays at 2.** Expressiveness was traded for an exactly enumerable space so the
  Bonferroni denominator is a number this code knows rather than an estimate. Depth 3 turns the
  correction into a guess and the whole significance story collapses.
- **A contradiction names the pair, never blames a field.** There is no ground truth about which of
  two disagreeing fields is wrong. Any UI that renders one side as "the error" is a bug.
- **`CONFOUNDED` is a feature, not a gap.** When conditioning cannot separate two overlapping
  cohorts, the tool names both and declines to pick. Every competing product prints both and sends
  the user to interrogate the wrong person. Do not add a tiebreak.
- **`PERVASIVE` is a real finding.** A defect no cohort explains means the field was never
  collected — a design gap, not an incident. Reporting it as localized sends someone hunting for an
  incident that never happened.
- **`HEALED` outranks nothing but changes everything.** A defect that stopped in January is scar
  tissue. Do not let the UI shout about it equally.
- **schema-default counterfeit needs both signals.** A declared-default flag *and* an anomalous
  share. Share alone is never enough — `United States` legitimately dominates a US company's CRM.
- **No chart library, no stats library, no date library.** Wilson, Bonferroni, the log-likelihood
  and every bar and interval are hand-rolled. Zero dependencies beyond Zod is part of the claim.
- **The corpus is generated, seeded and committed.** The app never generates at runtime. The
  generator source is the written spec of the eight planted pathologies, which is what keeps the
  tests honest instead of circular.
- **The corpus is synthetic.** Every domain ends in `.example`; no real company, person or email
  address is described. Pathologies are named, and each has a test named after it.
- **Medical metaphor lives in the README only.** Engine identifiers stay clinical-technical, UI copy
  stays plain. No "symptoms" tab, no "prescription" panel, no stethoscope. The name carries it.

## Gemini conventions (inherited from Days 001–009)

`@google/genai`, model `gemini-3.6-flash`, `responseMimeType: "application/json"` with a native
`responseSchema`, then Zod as the trust boundary — a schema is a request, a validator is a
guarantee. `ThinkingLevel.MINIMAL`: this is constrained classification against a fixed schema, not
reasoning. `temperature: 0`.

Missing key → **501** with a message pointing at the builder. Model failure → **502**. The app must
render every view, every finding, all vitals, the permalink and the CSV with `GEMINI_API_KEY`
unset, and the sweep asserts the deterministic findings are byte-identical either way. **The model
never detects, never localizes, never attributes and never resolves a confound** — its one job is a
verdict on strings that already survived all six deterministic counterfeit families.
